# 客户管理

> 设计状态：讨论中  
> 管理员端一级菜单：客户管理。

## 1. 二级功能页

**已确认**：客户管理下包含：

1. 客户；
2. 余额预警设置。

本轮先确定“客户”功能页；余额预警设置在后续单独细化。

## 2. 客户列表

客户功能页的主内容容器显示客户列表，并提供“新增客户”按钮。

建议列表至少展示：

- 客户编号；
- 用户名；
- 公司；
- 联系人；
- 邮箱；
- 手机号；
- 状态；
- EUR账户余额；
- GBP账户余额；
- 创建时间。

“账户余额”必须分别展示 EUR 和 GBP，不能合并为一个无币种金额。客户列表的搜索、筛选、排序和字段配置细节后续确定。

## 3. 客户详情

点击客户后打开客户详情标签，至少包含以下栏目。

### 3.1 基础信息

| 字段 | 规则 |
|---|---|
| 客户编号 | 系统自动生成、唯一、不可修改 |
| 用户名 | 客户主账号的登录名；唯一性规则后续确定 |
| 密码 | 不展示原密码；仅提供设置密码或重置密码操作 |
| 状态 | 正常、冻结、欠费 |
| 联系人 | 客户业务联系人 |
| 公司 | 客户企业名称 |
| 邮箱 | 联系邮箱 |
| 手机号 | 联系手机号 |
| 账户余额 | EUR与GBP分别展示；建议同时显示当前余额与可用余额 |

密码只能以不可逆哈希形式保存。管理员无法查看密码明文；客户忘记密码时通过管理员重置或后续自助找回流程处理。

### 3.2 客户状态

建议将状态解释为：

| 状态 | 含义 |
|---|---|
| 正常 | 可正常登录及使用满足余额要求的服务 |
| 冻结 | 管理员主动限制客户；允许登录，但仅可查看余额、账单和充值信息，不可下单或调用打单API |
| 欠费 | 客户至少一个币种账户为负数，由会计补扣形成；系统应自动反映该状态 |

欠费状态与服务限制保持一致：EUR欠费仅拦截EUR结算服务，GBP服务在余额正常时仍可下单。

## 4. 客户等级与客户分组

客户等级和客户分组由管理员后台维护，均包含唯一编号、名称与启用状态；系统不预设固定等级或分组。一个客户同时最多拥有一个当前等级和一个当前分组。

客户详情可设置归属及生效日期。每次调整自动关闭原归属、保留历史生效开始和结束日期；该历史用于按订单创建日期或会计指定计费日期匹配利润表。

## 5. API密钥

客户详情提供“API密钥”栏目，供客户将第三方系统接入开放API创建运单。

**已确认**：每个客户最多拥有一个有效API密钥，且仅管理员端可查看和管理；客户端不展示API密钥栏目。

密钥建议管理以下信息：

- 密钥名称；
- Key ID / 前缀；
- 密钥状态：启用、停用、已撤销；
- 权限范围；
- 创建人和创建时间；
- 最后使用时间；
- 失效时间，可选；
- IP白名单，可选。

安全规则：

- API Secret只在管理员创建或轮换时展示一次；
- 系统仅保存密钥摘要或加密后的安全材料，之后不能重新查看原文；
- 密钥丢失时必须创建新密钥并撤销旧密钥；
- 密钥调用产生完整的调用审计日志；
- API密钥由管理员按权限创建、停用、撤销或轮换；客户不可自行查看或管理。
- 管理员创建或轮换密钥后，应一次性通过安全渠道交付给客户，并记录交付时间、交付人和交付方式；不通过普通邮件、聊天记录或系统明文再次展示密钥。

## 6. 客户创建来源

**已确认**存在两种创建渠道：

1. 管理员在系统中创建客户；
2. 用户在客户端的登录／注册窗口自助注册。

无论来源如何，系统均应创建同一类客户企业、客户主账号和 EUR／GBP资金账户，记录来源：

```text
ADMIN_CREATED
SELF_REGISTERED
```

自助注册后是否需要管理员审核、是否立即可登录和下单，后续确定。

### 6.1 自助注册启用流程

**已确认**：自助注册后必须由管理员审核，并核对客户线下充值金额后，客户才可启用并下单。

为避免与“正常、冻结、欠费”混淆，建议独立维护开户状态：

```text
待审核 → 待核对充值 → 已启用
                 └→ 审核拒绝
```

“正常、冻结、欠费”属于客户使用状态；“待审核、待核对充值、已启用、审核拒绝”属于客户开户状态。未启用客户不能下单或调用打单API。

## 7. 建议的数据分层

为支持后续客户子账号与权限，建议不把所有数据压在一张“客户”表中：

```text
客户企业 Customer
├── 客户主账号 Customer Account
├── EUR资金账户 Customer Wallet
├── GBP资金账户 Customer Wallet
└── API密钥 Customer API Key
```

当前首版可默认一个客户企业对应一个主账号，但数据结构保留一对多账号扩展能力。

## 8. 余额预警设置（待讨论）

### 已确认

- EUR与GBP分别配置余额预警阈值；
- 预警阈值采用系统全局默认值，不按客户单独覆盖；
- 客户某币种余额低于对应阈值时，同时通知客户与管理员；
- 通知方式为站内消息；
- 预警按客户资金账户和币种独立判断，EUR预警不影响GBP预警。

### 建议的防重复规则

余额从阈值以上首次跌破阈值时发送一次站内消息；在余额恢复到阈值以上前，不重复发送相同低余额预警。恢复后再次跌破时，允许重新预警。是否需要增加每日或每周的未处理提醒，后续确定。

### 待确定

- 采用全局默认阈值、按客户覆盖，还是两者都支持；
- 通知方式：站内消息、邮件、短信或其他；
- 欠费、即将欠费是否使用不同预警级别；
- 是否需要避免同一客户重复发送预警。

## 9. 待确认问题

1. 自助注册客户在“待审核”或“待核对充值”期间，是否允许登录查看审核进度？
2. 管理员核对充值时，是直接为客户执行余额入账，还是先审核后由财务另行入账？
3. 唯一API密钥在何时创建：客户启用时自动创建，还是管理员在客户详情中按需创建？
4. 客户是否可以自行创建、停用本企业的子账号？
5. 一个登录账号是否允许属于多家客户企业？
6. 低余额预警是否需要增加每日或每周的未处理提醒？
