# 设计决策记录

## D-001：管理员端与客户端拆分

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：管理员端与客户端建设为两个不同的网站，两个前端连接同一个后端，通过不同身份与权限管理。
- **影响**：需要独立构建和部署；后端需要划分管理员接口、客户接口与数据访问边界。

## D-002：供应商接入需要可扩展

- **状态**：已确认
- **日期**：2026-08-01
- **决定**：需要同时支持官方接口、第三方供应商接口和中转站接口；每个接口供应方作为供应商管理。
- **设计建议**：供应商实例与接口协议驱动分离，相同协议尽量复用驱动代码。

## D-003：系统包含打单与账单

- **状态**：已确认
- **日期**：2026-08-01
- **决定**：系统必须同时覆盖打单、客户扣费、客户账单、供应商成本和对账，而非只生成面单。

## D-004：客户余额由管理员人工调整

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：系统不提供在线支付；管理员负责增加或减少客户余额，系统保留完整操作记录。
- **设计建议**：余额变更通过不可修改的资金流水完成，错误操作使用冲正流水，不直接修改或删除历史记录。

## D-005：首版资金币种

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：首版只支持 EUR 和 GBP，暂不支持 CNY。
- **设计建议**：每个客户按币种维护独立子账户，两种余额默认不能自动抵扣。

## D-006：管理员端一级功能划分

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：管理员端一级导航包含订单管理、客户管理、产品与渠道、报价管理、账单管理、数据统计；每个一级功能可折叠并包含后续讨论的二级菜单。
- **待补充**：原型中出现的“轨迹管理”是否作为一级功能尚未确认。

## D-007：管理员端采用多标签工作区

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：点击具体功能页后，在顶部打开以功能名称命名的标签，中间核心容器显示当前标签内容；切换功能时不进行浏览器整页刷新。
- **设计建议**：页面仍使用真实路由，以支持刷新恢复、浏览器历史和直接链接。

## D-008：管理员端导航与标签会话规则

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：首版不设置独立的轨迹管理一级菜单；顶部采用系统栏与标签栏上下两行布局；浏览器刷新时恢复已打开标签，用户退出后重新登录只打开首页。

## D-009：订单管理首批功能边界

- **状态**：已确认（细节讨论中）
- **日期**：2026-08-03
- **决定**：订单管理包含按状态的订单列表、高级搜索、字段配置、订单详情、人工创建、Excel 导入和开放 API 创建；管理员可代客户创建订单，客户可自行创建订单。

## D-010：订单状态、运单号与箱号关系

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：已下单表示订单已提交但尚未获得最终面单；已生成表示供应商已成功生成运单号和面单；已收货表示仓库或承运商完成收货扫描。提单号与运单号为同一业务字段，前端统一称为运单号；一票订单可有多个箱号，但只有一个承运商面单号。

## D-011：预估重量与箱号基础数据

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：用户创建订单时填写的重量在后台命名为“预估收费重”；供应商收货后的实重应单独保存。每个箱号包含重量、长、宽、高、品名、材质、英文名和申报货值。

## D-012：货品申报、最终收费重与订单标识

- **状态**：已确认（标识赋予规则待讨论）
- **日期**：2026-08-03
- **决定**：一个箱号允许包含多个不同品名的申报明细；最终收费重以供应商接口直接返回的数据为准；提取时间指承运商揽收时间。订单标识由管理员设计，例如用于标注超重等异常。

## D-013：申报货值与标识自动识别

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：每条货品申报明细包含数量、单件申报货值和币种，页面展示汇总后的总货值；供应商未及时返回最终收费重时，订单费用保持待确认。管理员可配置表达式规则为订单自动添加标识；箱号暂不设置独立状态。

## D-014：订单预扣与会计实际对账

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：客户下单时按预估收费重直接预扣对应币种余额，余额不足时禁止下单；不使用资金冻结。供应商返回实重和最终收费重后，由会计在账单管理中实际对账。订单物流状态与费用确认状态分离，订单可为“已生成”同时显示“最终收费重待确认”或“待实际对账”。

## D-015：提单取消、退款与会计确认

- **状态**：已确认（补扣规则待讨论）
- **日期**：2026-08-03
- **决定**：提供“取消提单”按钮，正常提单仅在供应商收货／拣货前允许取消；取消成功后才能退回原订单预扣金额。供应商调用结果未知时必须先查单，不能直接退款。会计实际对账后，如最终应收低于预扣金额，必须由会计确认后才退款。

## D-016：会计确认补扣与客户欠款

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：最终应收高于预扣金额时，由会计确认后补扣客户余额；余额不足时允许余额为负数并形成欠款。欠款只禁止使用该币种结算的渠道继续下单，不影响客户另一币种余额正常的渠道。

## D-017：客户打单风控分期

- **状态**：已确认
- **日期**：2026-08-03
- **决定**：首期优先完成基础打单和计费。后续建设客户打单风控，重点识别余额较低且连续以偏低预估重量打单的客户；风控依赖预估重量、供应商实际／最终重量、余额和对账数据。

## D-018：客户管理功能边界

- **状态**：已确认（细节讨论中）
- **日期**：2026-08-04
- **决定**：客户管理包含“客户”和“余额预警设置”两个功能页。客户页提供客户列表、新增客户、客户详情、EUR／GBP余额查看、客户API密钥及两种客户创建来源：管理员创建、自助注册。

## D-019：客户冻结、注册启用与API密钥

- **状态**：已确认（开户细节待讨论）
- **日期**：2026-08-04
- **决定**：冻结客户允许登录，但仅可查看余额、账单和充值信息；自助注册客户需经管理员审核并核对充值金额后，才能启用和下单；每个客户最多一个API密钥，且仅管理员端可查看和管理。

## D-020：API密钥安全交付

- **状态**：已确认
- **日期**：2026-08-04
- **决定**：API密钥由管理员创建或轮换后一次性安全交付给客户；系统不在客户端展示密钥，密钥原文也不支持再次查看。系统应记录交付审计信息。

## D-021：多币种余额预警

- **状态**：已确认
- **日期**：2026-08-05
- **决定**：EUR与GBP分别配置系统全局默认余额预警阈值；客户任一币种余额低于对应阈值时，同时通过站内消息通知客户与管理员。

## D-022：渠道与服务关系

- **状态**：已确认
- **日期**：2026-08-05
- **决定**：供应商打单接口配置为渠道；一个渠道可以提供多个服务，每个服务只能固定对应一个渠道。用户下单选择服务，后端依服务关联的渠道调用供应商接口。

## D-023：服务配置与报价表类型

- **状态**：部分由D-031替代
- **日期**：2026-08-05
- **决定**：服务配置可发国家、计费方式、计重方式、体积计算、尺寸精度、币种、计抛系数、清关方式、交货条款、计费重小数位、票计重精度、最小件数及最大票实重。成本表与利润表的归属关系见D-031。

## D-024：服务计费基础与渠道实例

- **状态**：已确认（预扣计算细节待讨论）
- **日期**：2026-08-05
- **决定**：系统重量、尺寸统一使用 kg、cm；服务计费方式为重量、体积或实重与材积重取大值；国家组仅支持欧洲国家；同一供应商允许配置多个渠道实例，例如不同账号、接口版本、测试或生产环境。

## D-025：体积与预估收费重计算

- **状态**：已确认（多箱汇总待讨论）
- **日期**：2026-08-05
- **决定**：体积计费按长×宽×高÷1,000,000得到m³，再按报价表的每立方米价格计算。实重与材积重取大值服务在预扣阶段，采用用户预估收费重与系统材积重的较大值。

## D-026：三段式重量报价计算

- **状态**：已确认（最低收费与按箱规则待讨论）
- **日期**：2026-08-05
- **决定**：重量报价表支持固定重量区间按票收费、超过阈值后按整票总重量乘每公斤单价、以及最低收费三个模块。超过阈值时，整票重量参与每公斤计费，不采用区间价加超出重量的方式；报价表与成本表共用该计算模型。

## D-027：多箱最低收费与按箱计重

- **状态**：已确认
- **日期**：2026-08-05
- **决定**：最低收费按每箱应用。按票计重时，整票基础价格与“每箱最低收费×箱数”取高；按箱计重时，每箱独立计算区间价／每公斤价并应用最低收费，订单价格为各箱费用之和。

## D-028：服务多件能力、可配置区间与附加费

- **状态**：已确认（附加费公式待讨论）
- **日期**：2026-08-05
- **决定**：服务配置是否支持一票多件；不支持时订单只能有一个箱号。重量报价表的区间和超阈值由各报价表配置，0–30kg不是系统固定规则。服务可选启用燃油费、超重费用和偏远地区费用。

## D-029：报价版本与附加费配置

- **状态**：已确认（附加费执行时点待讨论）
- **日期**：2026-08-05
- **决定**：服务利润表、供应商成本表支持多个版本及生效时间。燃油费按基础运费百分比计算；偏远地区通过可复用的邮编规则模板识别并可应用于多个服务；超重费用按服务使用前端表达式判断并计算收费。

## D-030：差异报价、偏远模板与超重费分阶段计算

- **状态**：部分由 D-032 替代
- **日期**：2026-08-05
- **决定**：客户利润表可按指定客户、客户等级或客户分组设置，优先级为指定客户、客户分组、客户等级、默认报价。偏远模板的最终绑定关系见 D-032。超重费用在预扣阶段按客户填写重量计算，在供应商实重返回后按实际重量计算最终费用；最终差额需会计确认后再调整余额。

## D-031：供应商成本表与服务利润表

- **状态**：已确认
- **日期**：2026-08-05
- **决定**：成本表绑定供应商，因为同一供应商成本固定；利润表绑定服务。客户基础运费等于匹配供应商基础成本加服务利润；服务利润支持成本百分比或针对成本价格行设置固定加价，且只基于基础成本计算。燃油、偏远、超重等附加费在基础客户运费之后按条件加收，不参与利润叠加。

## D-032：偏远地区服务配置与附加费金额精度

- **状态**：已确认
- **日期**：2026-08-05
- **决定**：每个服务最多绑定一个偏远地址模板。服务勾选收取偏远地区费用后，必须在服务中选择该模板并设置偏远费用金额；偏远地址模板在报价管理中集中维护，可被多个服务复用。燃油、偏远、超重三类附加费均在每一项规则计算完成后立即按服务币种保留两位小数，使用十进制定点金额与标准四舍五入；订单总价汇总这些已舍入的费用项。

## D-033：偏远地区费用不单列供应商成本

- **状态**：已确认
- **日期**：2026-08-05
- **决定**：偏远地区费只在服务中配置并作为客户应收费用项计入订单；供应商成本表不单独配置偏远地区费用，供应商应付成本中也不形成该费用项。

## D-034：FedEx 作为首个测试供应商

- **状态**：已确认
- **日期**：2026-08-05
- **决定**：首个供应商接入使用 FedEx 官方 REST API 测试环境。优先验证 OAuth 授权、创建面单、取消面单、查询／追踪及供应商调用异常处理；后续再按同一可插拔适配器模型接入 UPS、DHL、代理商和中转站。

## D-035：供应商最终数据的回传与账单导入兜底

- **状态**：已确认
- **日期**：2026-08-05
- **决定**：最终实重、最终收费重和供应商实际成本优先使用供应商接口回传或查单返回；不能可靠获取时，使用供应商账单 Excel 导入并匹配订单。每个供应商／渠道可以具有不同的数据来源与字段映射。匹配结果进入会计实际对账，任何补扣或退款仍须经会计确认后生成资金流水。

## D-036：尾程渠道、供应商连接与服务的正式关系

- **状态**：已确认并实施首期
- **日期**：2026-08-20
- **决定**：信息架构统一为“尾程渠道 → 供应商连接 → 服务”。尾程渠道仅用于区分 FedEx、UPS、DPD 等承运商类型；供应商连接代表一套实际账号、环境和接口驱动，可为官方、代理或中转商；服务只能绑定一个供应商连接。密钥、账号和 URL 仅保存于本地忽略的配置文件，前端通过驱动 schema 配置非敏感业务参数。被服务、成本表或账单引用的供应商连接只能停用，不能删除。

## D-037：尾程渠道按周期燃油附加费

- **状态**：已确认并实施首期
- **日期**：2026-08-31
- **决定**：燃油附加费属于尾程渠道，而不属于某个供应商连接或服务。同一尾程渠道的全部供应商连接及其服务共享同一套费率。管理员在渠道详情中维护费率、生效开始日期和结束日期，通常每周设置一条，也允许预设未来区间；同一渠道的日期区间不得重叠。报价与预扣取当前日期唯一命中的费率，未命中时燃油附加费为 0；订单费用明细保留当时的计算结果。

## D-038：服务利润表范围、归属历史与会计重算

- **状态**：已实现
- **决定**：服务利润表以服务详情为入口，可维护多个版本，并按指定客户、客户分组、客户等级或默认范围配置。匹配优先级固定为“指定客户 > 客户分组 > 客户等级 > 默认报价”。每个版本有默认利润规则，目的国有例外规则时优先使用例外、没有例外时使用默认规则，不回退到低优先级报价。版本可选择成本表作为矩阵来源，展示并导出成本加利润后的基础运费矩阵。客户等级和分组是可自定义主数据，客户当前归属唯一且保留带生效时间的历史。已生效利润版本可编辑但必须留存修改前后审计。会计重算默认使用订单创建日，也可指定计费日；按箱服务必须逐箱录入最终收费重。重算只保存结果和引用版本，不调整余额；仍由会计确认执行补扣或退款。

## 2026-09-16 UPS 官方驱动

新增 UPS_OFFICIAL，荷兰发货、管理员配置的欧盟 Standard 路线，固定服务 11，不覆盖 FedEx。供应商严格按编号使用独立 OAuth profile。创建 Shipping 中的 validate 本身创建运单，不进行第二次创建。四入口统一预检、报价预扣、持久化任务；原图和运单号先保存再做逐箱 4×6 PDF。整票取消需明确成功才建唯一会计退款待办；未知结果不自动重试。首期不接非欧盟清关、追踪和官方 Rating。见 [实施与配置说明](./13-ups-official-integration.md)。
## 2026-09-29：UPS 比利时始发扩展

UPS_OFFICIAL 在保留 NL 的基础上支持 BE 始发，按 profile 配置下发 Shipper/ShipFrom 国家；stateCode 可空。使用现有 JSON 路由快照记录始发国，未含该字段的历史 UPS 订单视为原有 NL 始发，阻止排队过程中错误换国出单。账号及环境取消保护不变，不扩大非欧盟/清关能力，不新增数据库迁移。
