# 客户资金与账单

## 1. 支持币种

### 已确认

首版只支持：

- `EUR`：欧元；
- `GBP`：英镑。

暂不支持人民币。

### 已确认的账户模型

每个客户分别拥有 EUR 和 GBP 子账户：

```text
客户资金账户
├── EUR：当前余额、可用余额
└── GBP：当前余额、可用余额
```

两种币种分别记账，默认不能自动互相抵扣。

若某个币种因会计确认补扣而产生负余额，只禁止使用该币种结算的渠道继续下单；另一币种余额正常时，客户仍可使用对应币种渠道下单。

## 2. 客户充值与人工调整

### 已确认

- 系统不接入银行卡、支付宝、微信或其他在线支付；
- 线下收款完成后，由管理员人工增加客户余额；
- 管理员可以根据业务需要减少客户余额；
- 系统必须保留完整操作记录。

### 建议方案

前端功能名称使用“余额入账”“余额扣减”“资金冲正”，避免让用户误认为存在在线支付。

每次调整至少记录：

- 客户；
- EUR 或 GBP；
- 增减方向；
- 金额；
- 调整原因；
- 线下收款编号或备注；
- 操作管理员；
- 操作时间；
- 调整前余额；
- 调整后余额；
- 唯一资金流水号。

资金流水创建后不允许编辑或删除。错误操作通过反向流水冲正。

## 3. 订单预扣与实际对账

### 已确认

首期不引入账期或信用额度：

```text
可用余额 = 当前余额
```

下单时按用户填写的预估收费重计算预扣金额，直接从订单结算币种的客户余额中扣除，不采用资金冻结。

1. 根据订单服务、预估收费重和报价表确定预扣币种及金额；
2. 检查对应币种可用余额；
3. 余额不足时禁止创建订单；
4. 余额充足时，订单创建与预扣资金流水在同一事务中完成；
5. 供应商成功生成面单后，订单保持正常物流状态；
6. 供应商返回实重和最终收费重后，订单费用进入会计实际对账；
7. 会计在账单管理中核对客户预扣、供应商实际成本和最终应收，完成差额处理。

供应商最终数据优先取接口回传或查单结果。若供应商（例如首期 FedEx 对接）未提供可靠的最终实重／最终收费重，则由管理员在账单管理上传该供应商账单 Excel；系统按照承运商运单号、渠道／账号、币种和账单周期等规则匹配订单，写入供应商实际数据并创建对账待办。无法唯一匹配、重复导入或数据冲突的记录必须进入人工处理队列，不能自动调整客户余额。

订单物流状态与费用状态分离：订单可以是“已生成”，同时费用显示“最终收费重待确认”或“待实际对账”。

已预扣金额只能在订单取消成功后退款：

- 正常订单在供应商收货／拣货前允许发起提单取消；
- 用户或管理员点击“取消提单”后，后端再次校验订单状态和供应商取消资格；
- 供应商确认取消成功，或未成功创建运单的订单完成内部取消后，系统才将该订单已预扣金额退回原币种余额；
- 供应商取消失败、已收货／拣货或结果仍未知时，不执行退款；
- 供应商调用结果未知时，必须先查单确认是否已创建，再决定取消路径，防止重复退款或遗留有效面单。

会计实际对账的差额规则：

- 最终应收低于预扣金额：会计确认后退回差额；
- 最终应收高于预扣金额：会计确认后补扣差额；
- 补扣时对应币种余额不足：允许余额变为负数，形成客户欠款，并只禁止该客户使用同币种结算的服务继续下单。

补扣和退款均必须关联原订单、会计确认记录和资金流水，不能直接修改客户余额。

## 4. 建议资金流水类型

| 类型 | 用途 |
|---|---|
| `OPENING_BALANCE` | 录入期初余额 |
| `ADMIN_CREDIT` | 管理员增加余额 |
| `ADMIN_DEBIT` | 管理员减少余额 |
| `SHIPPING_PRECHARGE` | 根据预估收费重直接预扣客户余额 |
| `CANCELLATION_REFUND` | 提单取消成功后退回原订单预扣金额 |
| `RECONCILIATION_DEBIT` | 会计对账后补扣差额 |
| `RECONCILIATION_REFUND` | 会计对账后退还差额 |
| `SURCHARGE_CHARGE` | 补扣附加费 |
| `SURCHARGE_REFUND` | 退还附加费 |
| `REVERSAL` | 冲正原资金流水 |

## 5. 客户销售与供应商成本

### 建议方案

订单需要分别保存：

- 客户销售金额及币种；
- 供应商预估成本及币种；
- 供应商最终成本及币种；
- 价格和汇率快照；
- 最终利润。

客户销售币种和供应商成本币种允许不同，但跨币种利润计算规则尚待确认。
