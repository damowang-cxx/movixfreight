## 1. 当前结论

项目已经完成“可运行的后端核心链路 + 双端运营页面”。它不是可直接投入生产的成品；下一阶段应优先完成真实 FedEx Sandbox 面单验收、报价快照、账单 Excel 文件接入及取消/退款闭环。完整验收步骤见 [当前开发进度与验收说明](../current-development-report.md)。

目前可以验证的核心闭环为：

```text
管理员创建客户与双币种钱包
  → 配置供应商 / 渠道 / 服务 / 成本表 / 利润表
  → 客户试算并创建订单
  → 按预估应收预扣余额
  → 管理员显式校验或创建 FedEx 面单
  → 供应商实际数据进入账单匹配
  → 财务应用账单并确认最终应收
  → 补扣 / 退款余额流水与欠费状态更新
```

其中“账单文件解析”仍未完成，故账单导入当前由已标准化的账单行录入承接。

|---|---|---|

## 4. 关键业务规则的当前实现

### 订单与资金

- 下单时按当前服务的币种，从同币种钱包扣除预估应收；余额不足或已为负则拒绝下单。
- 运单状态与费用状态分开保存。创建订单后为“已下单 / 已预扣”；账单应用后费用状态为“待对账”；会计确认后为“已对账”。
- 会计确认最终应收：高于预扣则补扣，低于预扣则退款。补扣允许余额变负，客户更新为欠费；系统不会使用 GBP 余额抵扣 EUR 欠款，反之亦然。
- 冻结客户不允许下单；当前实现没有单独的“仅允许查看余额与账单”前端权限页面。

### 供应商与 FedEx

- 所有供应商连接被视为可配置渠道；同一供应商可有多个渠道，每个服务仅绑定一个渠道。
- 当前首个连接是 FedEx Ship-API Direct 中转站，不是 FedEx 官方直连。密钥只从本地被忽略的 `config/connectors.local.json` 读取。
- FedEx Validate 仅校验载荷且记录审计；Create 前会再次 Validate。Create 是外部有副作用的操作，不能作为自动化测试步骤执行。

### 账单与对账

- 当前导入接口接收已经规范化的行：行号、运单号、供应商实重、最终收费重、供应商成本、币种和原始数据。
- 匹配后必须由财务显式“应用”才能写入订单实际数据；应用只产生待确认对账记录，不调整余额。
- 最终确认由财务输入最终应收，并在单一数据库事务中写入订单最终费用、资金流水和客户状态。

## 5. 数据库与运行环境

- 本地 Docker 服务为 PostgreSQL 16、Redis 7、MinIO；PostgreSQL 映射端口为 `15432`。
- 数据库 schema 已应用至当前本地开发库，Prisma Client 已生成。
- 当前 Windows/Node/Prisma 组合中，`prisma migrate dev` 曾返回无详细信息的 schema engine 错误。因此，仓库目前没有可供新环境直接执行的标准 Prisma migration 历史。
- 后续继续改表前，应先处理 Prisma/Node 版本兼容并补齐 migration 历史；在此之前，数据库变更必须由开发人员审阅生成的 SQL 后执行，不能把本地开发库当成可复现发布方案。
- 面单目前保存在开发数据库二进制列中；MinIO 已启动但尚未接入面单/账单源文件存储。
