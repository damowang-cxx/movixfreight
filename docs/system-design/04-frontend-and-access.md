# 前端应用与权限边界

## 1. 双前端模式

### 已确认

- 管理员端和客户端是两个不同的网站；
- 两个网站连接同一个后端；
- 两个网站功能、菜单和权限不同。

### 建议部署形式

```text
admin.example.com     管理员网站
portal.example.com    客户网站
api.example.com       统一后端
```

域名仅为示例，后续可调整。

## 2. 管理员网站建议功能

- 工作台；
- 客户、用户和权限；
- 全部订单和异常处理；
- EUR、GBP 余额调整；
- 客户资金流水；
- 承运商、供应商和接口账号；
- 供应商接口渠道、服务和价卡；
- 供应商成本；
- 客户账单与供应商对账；
- API 调用日志；
- 操作审计。

## 3. 客户网站建议功能

- 工作台；
- EUR、GBP 余额概览；
- 单票下单和批量导入；
- 订单查询和异常修改；
- 面单下载、批量打印和取消；
- 物流轨迹；
- 资金流水和客户账单；
- API 密钥和 Webhook；
- 客户子账号和权限；
- 企业资料。

## 4. 前端工程建议

两个网站独立构建、独立发布，但共享基础代码：

```text
frontend/
├── apps/
│   ├── admin-web/
│   └── customer-web/
└── packages/
    ├── api-client/
    ├── shared-types/
    ├── shared-utils/
    └── base-components/
```

管理员端偏向高密度运营操作，客户端偏向简洁的下单和账务体验。业务页面不强制共用，只共享基础组件、类型和 API 客户端。

## 5. 权限建议

管理员预设角色：

- 超级管理员；
- 运营人员；
- 财务人员；
- 客服人员；
- 接口技术人员；
- 只读审计人员。

客户预设角色：

- 企业所有者；
- 客户管理员；
- 打单操作员；
- 财务人员；
- 只读用户。

后端必须执行权限和客户数据范围校验，前端隐藏菜单不能作为安全措施。

## 6. 待确认

- 客户能否自行创建和停用子账号；
- 一个登录账号能否属于多家客户企业；
- 首版是否只有中文界面；
- 哪些管理员角色可以调整客户余额；
- 管理员端是否要求双因素认证；
- 两套网站是否都需要移动端适配。

管理员端的具体导航和标签交互见 [管理员端信息架构与多标签工作区](./05-admin-information-architecture.md)。
