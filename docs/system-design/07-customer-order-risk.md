# 客户打单风控（后续阶段）

> 设计状态：后续阶段  
> 前置条件：先完成基础打单、预扣、供应商重量回传和会计对账功能。

## 1. 目标

识别客户在余额较低时，连续以明显偏低的预估收费重创建订单的情况，并为运营、财务或风控人员提供及时的风险标识和处理依据。

该能力不是首期基础打单的前置条件。首期系统仅需完整沉淀预估收费重、供应商实重、最终收费重、客户余额和会计对账数据，为后续风控提供可靠数据基础。

## 2. 初步风险场景

```text
客户对应币种余额较低
且
连续多票订单的预估收费重低于供应商实际／最终收费重
且
低报差异超过管理员设定的阈值
→ 命中“低余额连续低报重量”风险
```

“连续”必须按供应商返回实际重量或最终收费重的时间顺序判断，不能只按客户创建订单时间判断。

## 3. 所需数据

- 客户及其 EUR、GBP 余额；
- 订单结算币种和所属渠道；
- 预估收费重；
- 供应商实重；
- 最终收费重；
- 供应商收货时间、返回重量时间；
- 会计对账结果及补扣／退款金额；
- 已命中的风险标识和处理记录。

## 4. 建议处理层级

初期仅支持风险标识、通知和人工复核，不自动拒绝订单。后续可逐步扩展：

1. 自动添加风险标识；
2. 通知运营与财务；
3. 要求人工审核后才允许下单；
4. 暂停客户特定币种或渠道下单。

## 5. 待确认

1. “余额较低”的阈值如何定义：固定金额、近期开单预计费用倍数，还是按客户配置？
2. “连续低报重量”的连续票数、低报比例和观察时间窗口分别是多少？
3. 比较基准使用供应商实重还是最终收费重？
4. 风控命中后的首个动作是标识、通知、人工审核还是直接限制下单？
5. 风控规则是否按客户、渠道、服务或币种分别配置？
