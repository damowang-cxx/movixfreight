# 管理员端信息架构与多标签工作区

## 1. 适用范围

本设计当前针对**管理员网站**。客户网站的信息架构和菜单将在后续单独讨论，不能直接复制管理员端菜单。

## 2. 一级功能导航

### 已确认

管理员端左侧导航包含以下一级功能：

1. 订单管理；
2. 客户管理；
3. 产品与渠道；
4. 报价管理；
5. 账单管理；
6. 数据统计。

每个一级功能都是可展开、收起的目录，下面显示对应二级菜单。各模块的二级菜单后续逐项讨论。

### 已确认的边界

- 首版不设置独立的“轨迹管理”一级菜单；
- 订单详情中仍可包含与该订单直接相关的物流信息；
- 后续如需要批量轨迹监控或轨迹异常工作台，再作为订单管理的二级功能评估。

## 3. 页面整体框架

### 已确认的结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 系统级顶部区域：标签工作区               通知 / 帮助 / 用户 │
├──────────────┬───────────────────────────────────────────────┤
│ Logo         │ 标签：首页｜订单列表｜客户列表｜……            │
├──────────────┤───────────────────────────────────────────────┤
│ 订单管理   ▾ │                                               │
│   二级菜单   │                                               │
│ 客户管理   ▾ │              当前标签内容容器                 │
│   二级菜单   │                                               │
│ 产品与渠道 ▾ │                                               │
│ 报价管理   ▾ │                                               │
│ 账单管理   ▾ │                                               │
│ 数据统计   ▾ │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

- 左侧导航在整个管理员会话中保持不变；
- 顶部标签栏显示已经打开的功能页；
- 中间核心容器显示当前激活标签的内容；
- 点击功能页时不进行浏览器整页刷新。

### 已确认的顶部布局

为了给多个标签留下足够宽度，建议把顶部拆为两行：

1. 系统栏：系统名称、通知、帮助、用户菜单；
2. 标签栏：首页和已打开的功能标签。

标签仍然位于页面顶端，但不会与通知、帮助、用户入口争抢同一行空间。

## 4. 多标签工作区行为

### 已确认

- 点击二级功能菜单后，在顶部打开以功能页名称命名的标签；
- 点击不同标签，只切换核心内容容器；
- 页面外壳、左侧导航和顶部区域不重新加载。

### 建议作为默认规则

1. **首页固定**：首页标签始终位于最左侧，不允许关闭。
2. **禁止重复标签**：再次点击已经打开的功能菜单时，激活原标签，不创建重复项。
3. **标签可关闭**：普通标签显示关闭按钮。
4. **关闭后的焦点**：优先回到最近访问的标签；没有其他标签时回到首页。
5. **标签溢出**：标签过多时支持横向滚动和标签列表，不无限压缩文字。
6. **右键或更多菜单**：支持关闭当前、关闭其他、关闭右侧和全部关闭。
7. **菜单联动**：切换标签后，左侧对应二级菜单保持高亮，其一级目录自动展开。
8. **未保存提醒**：编辑页面存在未保存内容时，关闭标签或离开页面需要确认。
9. **权限联动**：用户权限被撤销后，相关菜单与已打开标签一并失效。

## 5. 路由与页面状态

“不整体跳转”定义为单页应用内部切换，而不是不改变 URL。

### 已确认方案

- 每个标签仍对应一个明确 URL；
- 浏览器刷新后恢复当前已打开的标签及当前功能页；
- 浏览器前进、后退按钮仍然有效；
- 功能链接可以复制并在权限允许时直接打开；
- 标签切换时保留列表筛选条件、分页和必要的编辑状态；
- 重新进入长时间未使用的页面时重新请求数据，避免展示过期数据。

- 用户主动退出并重新登录后，仅打开首页，不恢复上次会话标签；

建议将“标签状态”和“页面缓存”分开管理，避免打开大量标签后长期缓存所有页面导致内存增长。

## 6. 标签唯一标识建议

普通功能页使用路由作为唯一标识：

```text
/orders                 订单列表
/customers              客户列表
```

带业务对象的页面使用“路由 + 对象 ID”：

```text
/orders/123             订单详情 · 123
/customers/88           客户详情 · 客户名称
```

这样可以在需要时同时打开多个订单详情，又不会重复打开同一个订单。

## 7. 视觉方向建议

管理员端是高频物流运营工具，视觉重点应是状态识别、信息密度和长时间使用的舒适度。

- 左侧一级目录使用稳定的深蓝灰或运输蓝作为结构色；
- 当前模块使用明确的高亮边线和浅色背景，不只依赖文字颜色；
- EUR、GBP、成功、异常、冻结等状态使用稳定且全站一致的语义颜色；
- 标签栏保持克制，避免每个标签都使用不同颜色；
- 表格和数字使用易对齐的数字样式，金额必须同时显示币种；
- 图标只辅助识别，不替代清晰的中文名称。

具体颜色、字体、间距和组件规范在技术选型确认后形成独立 UI 规范。
