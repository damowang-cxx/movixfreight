# 订单管理

> 设计状态：讨论中  
> 当前范围：管理员端订单管理。客户自助下单将复用同一订单模型与校验规则，客户侧页面稍后单独讨论。

## 1. 功能入口

| 功能 | 已确认要求 |
|---|---|
| 订单列表 | 按状态查看、查询、高级筛选、字段配置及进入详情 |
| 创建运单 | 管理员可代指定客户创建；客户也可以自行创建 |
| 人工创建 | 在页面中录入单票订单；原始表述为“人工上传”，具体按钮命名待确认 |
| Excel 导入 | 批量创建订单 |
| 接口创建 | 由客户系统调用开放 API 创建，前端不提供人工入口 |

三种创建方式必须进入同一套订单校验、计价、预扣、供应商打单和审计链路，不能因入口不同产生不同订单规则。

## 2. 订单列表

### 2.1 状态视图

订单列表按以下状态提供快捷筛选：

```text
全部｜已下单｜已生成｜已收货｜退件｜已取消
```

| 状态 | 定义 |
|---|---|
| 已下单 | 订单已提交，尚未获得最终面单 |
| 已生成 | 供应商已成功生成运单号和面单 |
| 已收货 | 仓库或承运商已完成收货扫描 |
| 退件 | 订单已进入退件流程或完成退件，细分状态后续定义 |
| 已取消 | 订单已取消，面单和资金处理规则后续定义 |

系统内部仍需保留“供应商下单中”“打单失败”“结果待确认”等技术状态，以正确处理接口超时与失败；这些状态是否在主筛选栏显示，后续结合运营流程确定。

### 2.2 高级搜索

高级搜索默认收起，可展开，并提供“查询”和“重置”。支持：

- 关键字；
- 运单号（提单号与运单号统一为此字段）；
- 服务；
- 用户名；
- 用户等级；
- 国家；
- 邮编；
- 收件人；
- 创建时间区间；
- 拣货时间；
- 签收时间；
- 提取时间；
- 标识。

拣货时间定义为供应商收货时间；提取时间定义为承运商揽收时间。

标识由管理员配置，用于标注订单的业务或风险情况，例如超重。一个订单可具有多个标识；标识的具体自动或人工赋予规则后续确定。

### 2.3 分页、排序和字段配置

每页最大显示数量提供 30、50、100 三档。

建议将用户的表格偏好按“用户 + 页面”保存，包括显示或隐藏列、列顺序、固定列、默认排序及每页显示数量。需要确认“用户自定义排序”是只指数据排序，还是同时包括表头字段顺序；当前设计默认两者都支持。

### 2.4 展示列

订单列表支持以下列，默认显示组合将在实际原型阶段确认：

1. 运单号；
2. 用户；
3. 服务；
4. 收件人；
5. 国家；
6. 件数；
7. 申报价值；
8. 实重；
9. 材重；
10. 预估收费重；
11. 报关方式；
12. 交税方式；
13. 承运商；
14. 主品名；
15. 标签；
16. 物品类型标签；
17. 备注；
18. 下单时间。

金额列必须显示币种；重量列必须显示单位。列表中不展示供应商成本和利润；管理员在订单详情的应付区域查看成本，具体权限后续定义。

## 3. 订单详情

点击订单行后打开订单详情标签。详情采用“顶部摘要 + 分区内容”，避免一张过长表单。

### 3.1 顶部摘要

- 服务；
- 目的国家；
- 预计收费；
- 订单状态。

### 3.2 快递数据

- 预估收费重；
- 供应商实重；
- 材重；
- 计抛系数；
- 体积；
- 箱数。

### 3.3 重量数据原则

用户填写的重量统一命名为**预估收费重**。供应商收货后返回的实重单独保存，不能覆盖客户提交的数据。

| 数据 | 含义 |
|---|---|
| 预估收费重 | 客户或管理员创建订单时填写的重量 |
| 箱实重 | 每个箱号的重量数据 |
| 供应商实重 | 供应商收货或称重后返回的实际重量 |
| 材积重 | 根据长、宽、高和计抛系数计算的重量 |
| 最终收费重 | 以供应商接口直接返回的数据为准，用于最终应收、应付和附加费对账 |

### 3.4 箱货明细

一票订单可包含多个箱号，但只有**一个承运商面单号 / 运单号**；不再区分提单号和运单号，前端统一显示“运单号”。

每个箱号至少包含：

- 箱号；
- 重量；
- 长、宽、高；
- 品名；
- 材质；
- 英文名；
- 申报货值（原描述为“申报物价”）。

一箱允许包含多个不同品名的申报明细。因此箱号与货品申报明细为一对多关系：箱号保存物理尺寸和重量；每条申报明细保存对应的品名、材质、英文名、数量、单件申报货值与币种。

申报金额计算规则：

```text
单条申报总货值 = 数量 × 单件申报货值
箱申报总货值 = 该箱全部申报明细总货值之和
订单申报总货值 = 全部箱号申报总货值之和
```

订单详情与创建页面均需展示订单申报总货值；展示时必须同时显示币种。

### 3.5 订单标识

标识由管理员设计和维护，用于订单列表筛选、异常识别与后续运营处理。例如“超重”标识可以提示运营人员该订单的预估重量、供应商实重或最终收费重存在超重情况。

每个订单标识至少需要保留：

- 标识名称与编码；
- 标识类型，例如异常、运营或财务；
- 标识来源，例如管理员手工添加或系统规则添加；
- 添加时间与操作人；
- 备注。

**已确认**：标识需要支持管理员配置的自动识别规则。规则至少需要定义触发时点、判断字段、比较条件、阈值、命中的标识和启用状态。例如在供应商返回实重后，当实际重量大于预估收费重且差值超过配置阈值时，自动添加“超重”标识。

标识规则采用受控表达式配置，支持多个条件组合。管理员不直接执行 SQL、JavaScript 或其他任意脚本；系统只开放订单字段、运算符和函数白名单，并在保存时校验表达式、在发布前用样例订单测试。

示例：

```text
destination_country == "GB"
&& supplier_actual_weight > estimated_chargeable_weight * 1.10
```

命中规则后执行“添加指定标识”。规则需要保留版本、启用状态、触发时点和执行记录，以便解释某票订单为何被自动标记。手工移除后是否允许规则再次自动添加，后续确定。

### 3.6 其他详情分区

- 物流信息；
- 应收：当前订单的客户费用明细；
- 应付：当前订单的供应商成本明细。

物流信息是订单详情的一部分，不代表建立独立轨迹管理模块。应收、应付只能在管理员具有对应财务权限时展示。

### 3.7 费用确认状态

订单状态与费用确认状态分开显示：

| 费用确认状态 | 含义 |
|---|---|
| 已预扣 | 已按预估收费重从客户余额直接扣除预扣金额 |
| 最终收费重待确认 | 供应商尚未返回最终收费重 |
| 待实际对账 | 供应商已返回实重或最终收费重，等待会计在账单管理核对 |
| 已完成对账 | 客户预扣、供应商成本和最终应收已完成核对及差额处理 |

余额不足时禁止下单。费用状态不替代“已下单、已生成、已收货”等订单物流状态。

当最终应收低于预扣金额时，差额先显示为“待会计确认退款”；会计确认后才创建退款资金流水并退回客户原币种余额。

当最终应收高于预扣金额时，差额先显示为“待会计确认补扣”；会计确认后从订单原币种余额补扣。若余额不足，允许该币种余额变为负数并形成欠款，同时只禁止该币种结算渠道继续下单。

### 3.8 取消提单与退款

订单详情提供“取消提单”操作。该操作不是直接退款按钮，而是“取消成功后退款”的前置动作。

取消流程：

```text
发起取消提单
→ 校验订单未供应商收货／拣货
→ 调用供应商取消或完成内部取消
→ 取消成功
→ 退回该订单原预扣金额
```

规则如下：

- 正常订单在供应商收货／拣货前可以取消；
- 点击取消时必须由后端再次校验取消资格，不能仅依赖前端展示；
- 供应商取消成功后自动退款至客户原币种余额；
- 供应商明确下单失败的订单也必须完成内部取消后才能退款；
- 供应商调用结果未知时，先查询是否已创建运单，再决定取消或保留预扣，不可直接退款；
- 已收货／拣货、供应商拒绝取消或取消结果未知时，订单不退款。

## 4. 创建运单

### 4.1 创建主体

- 管理员可以为指定客户创建订单；
- 客户可以为自己创建订单；
- API 可以代表已授权客户创建订单。

管理员代客创建时，必须明确选择客户，创建记录需保留实际操作管理员和订单归属客户。

### 4.2 已确认的填写分组

创建运单至少包含：

1. 服务：可选择不同供应商提供的 UPS、FedEx、DHL 等服务；
2. 收件人信息；
3. 清关方式；
4. 箱号数据。

收件国家支持国家表中的中文名或 ISO 两位代码，保存和试算前统一规范为 ISO 代码；省/州为可选字段。箱号可留空，由系统在订单号生成后按 `ORD-…-001` 规则补齐；Excel 中空箱号的每一行申报明细视为独立箱。

订单列表和详情已经出现申报价值、报关方式、交税方式、箱货数据等字段，因此创建表单还需在后续讨论中补齐税务、备注和实际操作规则。

### 4.3 Excel 与 API

Excel 导入和接口创建不在前端手动下单页展示，但均应产生可定位的创建来源：

```text
MANUAL（人工创建）
EXCEL_IMPORT（Excel 导入）
OPEN_API（接口创建）
```

建议导入任务返回逐行校验结果；错误行不应静默失败，需能下载错误原因并修正后重新导入。

3. “人工上传”是否指人工单票录入，前端是否改名为“人工创建”？
4. 用户自定义排序是否同时包含数据排序和字段顺序？
5. 订单详情是否允许同时打开多个不同订单标签？
