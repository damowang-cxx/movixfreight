# 当前开发进度与验收说明

> 更新日期：2026-09-02  
> 结论：系统已形成可在本地环境联调的“配置 → 报价 → 预扣 → 管理员显式 FedEx 打单 → 账单匹配 → 会计对账”主链路；仍是开发原型，尚不具备生产上线条件。

## 1. 已实现的业务闭环

```text
客户与 EUR/GBP 钱包
  → 供应商 / 渠道 / 服务配置
  → 成本版本 + 利润版本 + 附加费配置
  → 管理员或客户创建订单、试算与预扣
  → 管理员 Validate / Create FedEx 面单、浏览器打印 PDF
  → 供应商账单标准化录入、匹配和应用
  → 会计确认最终应收、补扣或退款
```

FedEx 当前作为正式“供应商与渠道”中的 `FEDEX_RELAY` 驱动使用。Sandbox/Production 是供应商连接环境属性，不会改变客户、订单、服务或报价的页面结构。新订单改为先选择供应商连接、再填写目的国；后端只会在该供应商已配置唯一启用国家路由时，自动选择内部计价服务与实际 FedEx `serviceType`。当前本地连接配置仅用于 Sandbox 联调；不会自动调用生产接口。

## 3. 已锁定的重要规则

- 资金只在同币种钱包中流动：EUR 欠款不使用 GBP 抵扣，反之亦然。
- 订单状态和费用状态分离。订单生成面单不代表费用已经最终确认。
- 下单先按试算金额预扣；供应商账单应用只形成待对账记录；只有会计确认才补扣或退款。
- 补扣可使对应币种余额变为负数，并将非冻结客户标记为欠费；欠费币种关联服务会被禁止继续下单。
- 偏远费需同时满足：服务启用、服务绑定模板、国家和邮编命中。规则只支持精确邮编和邮编前缀，避免执行任意表达式。
- 体积按 `cm³ ÷ 1,000,000` 转 m³；“实重与材积重取大”按服务计抛系数处理。
- FedEx Create 是有外部副作用的动作：管理员必须显式点击；并发调用由 `SUBMITTED → GENERATING` 原子转换保护；未知结果不自动重试。
- 客户 API Key 每客户仅一把，数据库只保留 bcrypt 哈希；明文只在管理员创建或轮换时展示一次。
- 箱号、实重、长、宽、高始终必填；其余申报字段由超级管理员配置。原产国和材质默认可选，但选择 FedEx 服务时，英文品名、原产国、HS 编码、数量、单件申报货值、申报币种仍由接口规则强制必填。

## 4. 推荐验收顺序

### 运行前检查（本次核对：2026-08-10）

- Docker 的 PostgreSQL、Redis、MinIO 容器均在运行；PostgreSQL 使用宿主机端口 `15432`。
- API 健康检查 `http://localhost:3000/api/health` 当前无法连接，说明 API 进程尚未启动或已停止。开始手动验收前，需在项目根目录启动 `pnpm dev`；如果此前启动的是旧 API 进程，应先重启，使最新代码生效。
- 前端默认地址为管理员端 `http://localhost:3001`、客户端 `http://localhost:3002`；API 启动后可通过 `http://localhost:3000/api/docs` 查看 Swagger。

### A. 不涉及 FedEx 外部调用

1. 管理员登录后，在“客户”新建普通客户；确认系统自动创建 EUR/GBP 钱包。
2. 为客户 EUR 钱包人工入账；在“余额预警设置”配置低余额阈值并验证站内提醒。
3. 在“供应商与渠道”创建/选择尾程渠道和供应商连接；在“服务管理”创建服务并绑定供应商连接。
4. 在“供应商成本表”创建成本表头，录入国家组、适用范围和币种；进入成本表详情下载模板或粘贴矩阵，为每个国家/邮编价格列维护最低票、最低箱、挂号和操作费，预览后整表写入价格。再创建生效服务利润版本。
5. 选择一个服务配置燃油费；如需偏远费，在“偏远地址模板”创建邮编规则并绑定服务。
6. 在“创建运单”选择客户和服务，录入收件地址、箱子尺寸/重量、申报明细，点击“试算”，确认成本、利润、体积、计费重、附加费和预计应收。
7. 提交订单并检查相同币种钱包的预扣流水；余额不足时应被拦截。
8. 使用 Excel 模板导入同类订单，先检查预校验，再确认创建；重复确认同源内容不得重复预扣。
9. 在“供应商账单导入”录入已标准化的账单行，应用匹配后到“订单对账”先执行重算（按箱服务须填每箱最终收费重），确认重算金额后再会计确认；核对补扣/退款流水。

### B. FedEx Sandbox 联调

前提：本地 `config/connectors.local.json` 的密钥、账号、发件人信息均完整；创建的渠道环境与该配置一致；订单的服务代码、收件地址和申报数据符合 FedEx Sandbox 要求。

1. 在订单列表打开刚创建的订单，先点击 `Validate`。
2. Validate 成功后，由管理员明确点击“生成面单”。
3. 成功时应出现承运商运单号和 PDF 标签；点击“打印 PDF”会在浏览器新标签打开标签。
4. 如果供应商明确拒绝，订单应进入 `FAILED`；超时、网络或未知结果应进入 `UNKNOWN`，不得再次自动 Create，需人工核查。

> 不建议在未核对 Sandbox 要求前直接点 Create。本报告不把源码编译成功视为真实面单已生成。

## 6. 后续开发规划

1. 使用真实 FedEx Sandbox 数据完成一次 Create/PDF 打印人工验收，并把结果和请求限制写入实施记录。
2. 已实现 FedEx 单票取消；下一步补齐查单与轨迹。取消退款仍必须按订单状态、供应商响应和会计确认分阶段处理。

5. Open API 限流、完整订单/轨迹、服务、余额、报价、取消与 Webhook 回调能力。

### P2：生产化与风控

1. Prisma migration 历史、对象存储、异步任务、调用重试策略和审计脱敏。
2. CI/CD、监控告警、备份恢复演练、权限与安全测试。
3. 低余额下连续低报重量等打单风控规则，并在积累足够真实订单和供应商重量数据后启用。
